# Hyprshell security, reliability and efficiency audit — 2026-10-27

This pass builds on the October 26 audit. It reviewed the installed/repository
copies, shared QML controls, notifications and drawer lifecycles, wallpaper
queries, dashboard counters, weather persistence, and selected update, cleanup,
network and IPC safety paths. The initial checkout was clean. It is a focused
source/runtime audit, not an exhaustive dependency-advisory or OS security scan.

## Fixed

| Finding | Change |
| --- | --- |
| Shared controls could interpret application/device names, notification actions, cleanup paths and other external labels as markup. | Menu/app buttons, Settings buttons/selectors/switches/check boxes, app identity details and custom weather/cleanup delegates now explicitly use plain text. Existing styles and actions remain intact. |
| Weather atomic writes opened a predictable temporary path with truncation and default permissions. | Exclusive creation rejects pre-existing files and symlinks, new files use mode 0600, writes are flushed before replacement, and failed replacements clean up only the temporary file created by that attempt. |
| Failed wallpaper queries discarded the previous wallpaper/color mapping. | Apply output only after successful exit. Repeated failures back off from 4 seconds to a maximum of 30 seconds; success restores the normal 2-second interval. Successful empty output still clears absent outputs. |
| Weather search/save commands that exited unsuccessfully without JSON left misleading or absent feedback. | Display a retryable search/save error, preserving structured errors from the helper. Cached forecasts retain their existing quiet offline behavior. |
| Dashboard uptime stopped advancing while the drawer remained open. CPU sampling read and split the entire per-core/interrupt table. | Refresh uptime with each existing sample and read only the aggregate CPU line. Static system discovery still runs once per helper invocation; sampling still stops when the drawer closes. |
| The activity drawer repeatedly rebuilt a large wallpaper pixel strip when its geometry changed. | Use the existing dashboard thumbnail-cache approach: a 96×64 RGBA buffer, sampled regionally as the drawer moves/resizes. Native checks verify the same pixel buffer is retained and different wallpaper regions still produce different colors. |
| Eight Qt assertions still expected the media spectrum's old square dimensions. | Update only the stale expectations for the intentionally wider/taller spectrum and slightly smaller title. Retain checks for centering, pill bounds, vertical padding and circular/side layouts. No panel design change. |

Qt explicitly warns that automatically detected text markup can load remote
images; plain text is the appropriate boundary for these external labels.
See [Qt Quick Text security guidance](https://doc.qt.io/qt-6/qml-qtquick-text.html#details).
The weather temporary-file finding is local filesystem hardening, not a
demonstrated remote execution or privilege-escalation path. Existing home-directory
permissions already restrict other users; this change does not alter them or
rewrite saved locations/caches.

## Performance evidence

- In an isolated five-repeat benchmark of 300 calls per repeat, aggregate CPU
  sampling fell from **44.6 to 18.6 microseconds per call** (median). The sampled
  `/proc/stat` contained 5,337 characters; its aggregate line had 62. These are
  helper timings under that test load, not whole-desktop CPU savings.
- At the activity test's 1100-pixel screen width and a drawer at least 160 pixels
  tall, the previous RGBA buffer was **704,000 bytes**. The replacement is
  **24,576 bytes**, about **96.5% smaller**, and is retained across geometry changes.
  This measures the sampled buffer, not total Qt/GPU memory or rendered frame time.
- Once wallpaper failure backoff reaches its cap, retry opportunities fall from
  30 to 2 per minute. Recovery can then take up to 30 seconds. Normal successful
  polling and external wallpaper-change detection remain unchanged.

## Release caveat and further improvements

The weather source and local executable are fixed, but `app-releases.json` still
pins the existing published v1.0.0 executable. Full setup or reviewed deployment
can replace the locally rebuilt weather helper with that older asset. A new
published desktop-app release and updated checksum are needed to distribute this
Rust fix through that channel. No release assets, tags or remote branches were
published by this task. The ordinary QML/Python fixes are in the synced payload.
The weather README now distinguishes development builds from release installation.
For a deliberate local rebuild:

```sh
cargo build --release --locked --manifest-path apps/hyprweather-rs/Cargo.toml
install -m 755 apps/hyprweather-rs/target/release/hyprweather \
  "${XDG_CONFIG_HOME:-$HOME/.config}/quickshell/helpers/hyprweather"
```

The next useful optimization targets are:

1. **Large notification histories:** history serialization rewrites all rows and
   expanded groups create one card per notification. Benchmark large synthetic
   histories, then coalesce writes with reload/exit flushing and virtualize cards
   while preserving all history and actions. No retention limit was imposed.
2. **Successful wallpaper polling:** an event-driven source could remove the
   remaining two-second subprocess launches. It must still notice wallpapers
   changed outside Hyprshell and handle daemon restarts/hotplug.
3. **Host measurements:** compare shell RSS, idle CPU and frame timing during
   drawer animation, audio playback and multi-monitor changes. Preserve animation
   cadence and accessibility settings; measure before changing sampling policies.
